# Демо-видео V2 (3–5 минут) — сценарий по минутам

Запись ведётся поверх запущенного Streamlit-демо (`demo/app.py`, 8 экранов в боковой панели) и
`REPORT.md`. Все цифры — из демо (оно считает их само из сохранённых данных) и из
`results/main_table_v2.md`, `results/spend_summary.md`; руками ничего не подставлять. Видео
записывает автор, не ассистент. Поднять демо заранее и прогнать сценарий вживую хотя бы раз:

```bash
python -m venv .venv-demo && source .venv-demo/bin/activate
pip install -r requirements-demo.txt
streamlit run demo/app.py
```

## 0:00–0:25 — Вопрос и зачем он Document AI

**Показать:** заголовок и первый абзац `README.md`.

**Сказать:** «R04: при каких объёмах документов и типах вопросов передача всего корпуса в
контекст (long context) выигрывает у RAG — поиска с передачей модели только релевантных
фрагментов — и наоборот. Для Document AI это вопрос экономики. Сравнение честное: один промпт,
одна модель — `gpt-6-luna`, один судья; различается только то, как собирается контекст.»

## 0:25–1:00 — Экран «Ответ на исследовательский вопрос»

**Показать:** главный экран: четыре карточки сверху, переключатель размера на **100K**, набор **A-hard**, таблица методов.

**Сказать:** «Это ответ на вопрос целиком. Карточки: лучше всех по цене и качеству — BM25; LC дороже RAG за
вызов примерно в 28 раз; EMB без лексической подсказки падает с 0.94 до 0.44; на пустом контексте
модель не отвечает ни разу — утечек нет. В таблице точность с доверительным интервалом, evidence
recall, отказы и цена верного ответа. Важно: после поправки Холма ни одна пара методов не
различается значимо — решает цена и поведение эмбеддингов.»

## 1:00–1:30 — Экран «Якорь: с именем и без»

**Показать:** график по трём размерам (закрашенный круг — с якорем, пустой ромб — без) и таблицу парного теста.

**Сказать:** «Главная ось работы: один и тот же факт спрашиваем с названием сущности и без. LC, BM25 и
гибрид с реранкером этого не замечают. Эмбеддинги теряют факт: на 100K девять вопросов верны только с
якорем, ни одного — только без. Парный тест даёт p = 0.0039, но после поправки Холма 0.059 — не значимо.
При 18 парах тест вообще способен подтвердить только очень большую разницу, поэтому это тенденция, не доказанный эффект.»

## 1:30–2:00 — Экран «Деньги»

**Показать:** калькулятор: 10 000 вопросов в месяц, корпус 100K, доля кэша 0 → 90%, переключить Luna / Terra.

**Сказать:** «Плашка сверху — главное: кэш провайдера между разными вопросами в наших замерах не сработал,
поэтому цены холодные, а ползунок кэша — сценарий «а что если». Без кэша LC на 100K не окупается вообще;
с кэшем 90% граница сдвигается. Self-Route и агент показаны рядом с точкой безубыточности.»

## 2:00–2:30 — Экран «Агент»

**Показать:** агент BM25, тип T2, любой эпизод: шаги search_corpus → get_chunk → ответ, карточки с числом вызовов, `tool_call_accuracy`, ценой; раскрыть страницу Notion-мока.

**Сказать:** «Вместо готового контекста модель сама ищет: ищет, читает фрагмент, считает, отвечает. Здесь около
четырёх вызовов инструментов, все структурно корректные, цена чуть выше RAG. Notion — мок без сети; в зачётных
прогонах запись выключена, на экране предпросмотр того, что было бы записано.»

## 2:30–3:15 — Экран «Бонус-проверки»

**Показать:** четыре вкладки с пометкой «постфактум».

**Сказать:** «Четыре проверки после основных прогонов. Эмбеддер bge-m3 вместо OpenAI слегка улучшает EMB, но
BM25 всё равно заметно лучше — провал не объясняется выбором эмбеддера. Более сильная модель Terra на тех же
контекстах не меняет ни одного вердикта — провал в поиске, а не в читателе. OP-RAG, порядок чанков как в
документе — результат на вкладке. Self-Route и роутер — симуляция по сохранённым ответам: при хорошем поиске
отказов почти нет, выигрыша нет; для слабого EMB Self-Route помогает, но BM25 дешевле и лучше.»
