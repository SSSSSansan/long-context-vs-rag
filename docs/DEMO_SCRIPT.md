# Демо-видео V2 (3–5 минут) — сценарий по минутам

Запись ведётся поверх запущенного Streamlit-демо (`demo/app.py`, экраны 1–5 из сайдбара) и
`REPORT.md`. Все цифры ниже — из `results/main_table_v2.md`, `results/spend_summary.md` и самого
демо (оно само их считает из сохранённых `results/*`, ничего руками не подставлять). Поднять
демо заранее и прогнать сценарий вживую хотя бы раз до записи:

```bash
python -m venv .venv-demo && source .venv-demo/bin/activate
pip install -r requirements-demo.txt
streamlit run demo/app.py
```

## 0:00–0:25 — Вопрос и зачем он Document AI

**Показать:** заголовок и первый абзац `README.md`.

**Сказать:** «R04: при каких объёмах документов и типах вопросов передача всего корпуса в
контекст (long context) выигрывает у RAG — поиска с передачей модели только релевантных
фрагментов — и наоборот. Для Document AI это прямой вопрос экономики: платить за то, что модель
читает весь корпус на каждый вопрос, или строить поиск. Сравниваем честно: один промпт, одна
модель — `gpt-6-luna`, один судья для всех методов; различается только то, как собирается
контекст.»

## 0:25–1:05 — Экран 1 «Один вопрос — разные методы»

**Показать:** демо, экран 1. Выбрать набор **A-hard**, размер **100K**, тип **T2** (сравнение),
включить тумблер «Показать гибрид и агента» — выбрать любой конкретный вопрос.

**Сказать:** «Один и тот же вопрос параллельно уходит в LC (весь корпус), BM25, эмбеддинги,
гибрид и агента с поиском. Видно дословно, что каждый метод реально получил на входе — у RAG
это найденные фрагменты, золотой отмечен звёздочкой, у LC — что факт физически есть в тех ста
тысячах токенов. Карточка показывает вердикт, цену именно этого вызова и время ответа — это не
усреднённая цифра из таблицы, а то, что произошло на этом конкретном вопросе.»

## 1:05–1:45 — Экран 2 «Точность и размер корпуса»

**Показать:** демо, экран 2. Набор **A-hard**, метрика «Основная», все методы включены.

**Сказать:** «Это главный график: точность с 95%-доверительным интервалом Уилсона по размеру
корпуса. На A-hard (вопрос без лексической подсказки — нужно понимание смысла) эмбеддинги и
гибрид без реранкера заметно проседают с ростом корпуса — на 100K эмбеддинги 0.44 против 0.98 у
LC. Но справа — честная карточка: из всех парных тестов Макнемара с поправкой Холма **значимых
различий между методами почти нет** — на наборе A, где у вопроса есть лексическая подсказка, все
методы 0.93–1.00, это потолок, различий не видно вообще.»

## 1:45–2:25 — Экран 3 «Деньги»

**Показать:** демо, экран 3. Набор A-hard, прокрутить к «Когда LC может окупиться», переключить
размер на 100K.

**Сказать:** «По стоимости разница однозначная, даже когда по точности не доказана: LC на 100K
дороже RAG примерно в 28 раз за один вызов. Важная оговорка прямо на экране: кэш провайдера
между РАЗНЫМИ вопросами к одному корпусу у нас не сработал — `cached_tokens` был 0, поэтому
кривая «LC с кэшем» здесь теоретическая, по формуле, не измеренная. Без кэша точка безубыточности
LC на 100K не наступает вообще.»

## 2:25–2:55 — Экран 4 «Положение факта»

**Показать:** демо, экран 4.

**Сказать:** «Два эксперимента: P1 — двигаем факт по корпусу от начала к концу у LC, проверяем
эффект Lost in the Middle; P2 — ставим золотой фрагмент на ранг 1, 5 или 10 в выдаче RAG.
Эффекта не нашли ни там, ни там. Но это не «эффекта нет» — это потолок при маленькой выборке,
6–13 вопросов на точку, честно сказано прямо под графиком.»

## 2:55–3:35 — Экран 5 «Выводы»

**Показать:** демо, экран 5 — карточки и таблица значимых различий внизу.

**Сказать:** «Свод по карточкам: LC имеет смысл до ~8K при простом пути без инфраструктуры;
дальше — BM25 или гибрид с реранкером; агент с поиском хорош там, где нужно сравнение или
противоречие без явной зацепки за текст; чистые эмбеддинги — самое слабое место. Таблица внизу —
это единственные пары, которые прошли поправку Холма: в основном это «любой метод лучше
отсутствия контекста», различий между содержательными методами при таком n почти нет.»

## 3:35–4:15 — Итоги и ограничения

**Показать:** блок «Итоги и ответ на исследовательский вопрос» в начале `REPORT.md`.

**Сказать:** «Короткий честный ответ на исследовательский вопрос: статистически доказанного
превосходства LC над RAG или наоборот мы не нашли ни на одном размере корпуса, ни на одном типе
вопроса. Рекомендации на предыдущем экране — это направление точечных оценок и экономика, а не
доказанная значимость. Бюджет: потрачено $2.23 из лимита $3.00, разбивка по шагам — в
`results/spend_summary.md`. Калибровка судьи сделана на 40 примерах одним проверяющим, не
независимой двойной разметкой — это тоже ограничение, не финальная цифра.»
